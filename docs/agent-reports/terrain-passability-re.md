# 地形通行層（collision.bmp）與水深、坡度、材質之統計關聯逆向分析報告

- **日期**：2026-10-14
- **執行代理**：Antigravity（承接 Codex 中斷之 Rust probe）
- **關聯工作**：`docs/agent-reports/terrain-gap-audit.md`（Gap 2：全域高度／水位／材質修改未同步通行層）
- **核心結論**：**不實作全域自動更新通行層，保留設計者手動畫記**。統計全版 73 張官方零售地圖（4,669,440 網格）證實：`collision.bmp` 與水深、坡度、地表材質均**無可靠決定性對應關係**（全規則平均 Precision／Recall 遠低於 0.95 門檻；達標地圖比例介於 0% 至 6.8%）。依指示不合成猜測性通行規則，停止新增覆寫程式碼。

## 一、背景與問題定義

在 `docs/agent-reports/terrain-gap-audit.md` 中，已於 `TerrainHeightEditSession.PaintWater` 實作局域水域筆刷同步碰撞層（將筆刷範圍內且低於水面之未阻擋像素 0 改為 255，不清除既有手工阻擋）。然而，針對全域高度升降、全圖水位修改、坡度雕刻與地表材質（Texture）變更，先前並未自動更新 `collision.bmp`。

本任務旨在透過統計逆向工程，回答以下核心問題：
> 原版 Against Rome 官方地圖的 `collision.bmp`（通行阻擋層），是否由地形高度圖（`boden.bmp` × `Heightmapstep` 與 `boden.ini` 的 `[Waterlevel]` 之相對水深）、地表坡度（相鄰高程差）、或地表材質（`boden.txt` 的 `[Texturen]`）單獨或聯合決定？若存在可靠規則（多數地圖 Precision 與 Recall > 0.95），則實作安全局域更新；若不可靠，則以數據為證，停止程式碼變更。

---

## 二、Codex 中斷探針修復（Root Cause & Fix）

Codex 代理先前編寫之 Rust 探針 `TEMP/terrain-passability/probe.rs` 在執行時 panic 終止：
`panicked at 'missing [Heightmapstep]'`

### 原因診斷
1. 原版 `boden.ini` 中，許多區段標頭帶有行內德文註解，例如 `[Heightmapstep]      ;1..` 或 `[Waterlevel]         ;0..`。原 probe 採用 `l.trim().eq_ignore_ascii_case(key)` 直接比對整行，未先剝除分號 `;` 後之註解，導致比對失敗。
2. 此外，部分地圖可能省略 `[Heightmapstep]`；依據編輯器載入邏輯（`MapEditorForm.cs`）：
   ```csharp
   _nativeHeightMapStep = float.TryParse(ini.GetValue("Heightmapstep"), ...) ? heightStep : float.NaN;
   _heightMapStep = float.IsFinite(_nativeHeightMapStep) ? _nativeHeightMapStep : 4;
   ```
   官方引擎與編輯器之標準預設值為 `4`（`[Waterlevel]` 預設為 `0`）。

### 修復措施
在 `probe.rs` 實作強健解析函式 `val_or`：
- 自動以 `;` 分割行，並對標頭與鍵值去空白。
- 支援大小寫不敏感比對。
- 當鍵不存在或無法解析時，回退至標準預設值（`Heightmapstep = 4`, `Waterlevel = 0`）。
- 補齊 Rust 2021 Edition 相容性與型別轉換。

## 三、資料集與檢測架構

- **來源路徑**：`C:\Program Files (x86)\Against Rome\MAPS`（唯讀掃描，嚴禁修改）。
- **地圖母體**：共 73 張官方原版零售地圖（排除 `arm_custom_maps.json` 記載之使用者測試圖 `ENDL_005`）。
- **圖層尺寸多樣性**：
  - 教學地圖（`TUTOR_00` ~ `TUTOR_03`）：碰撞層 192×192，高度層 193×193（網格數 36,864 × 4 = 147,456）。
  - 標準地圖（`ENDL_*`, `HIST_*`, `KAMP_*`, `MP_*` 共 69 張）：碰撞層 256×256，高度層 257×257（網格數 65,536 × 69 = 4,521,984）。
  - **總分析網格數**：**4,669,440 個 collision cells**。
- **高程模式**：
  - **Raw 模式**：原始綠通道高程 × `Heightmapstep`。
  - **Smoothed 模式**：依據 `smooth.bmp` 進行多輪權重平滑（模擬原生引擎 LDFLOORHMAP 平滑管線）。
- **檢驗特徵**：
  1. **相對水深 $d$**：$4 \times \text{Waterlevel} - (h_{0,0} + h_{1,0} + h_{0,1} + h_{1,1})$（正值代表水面下四分位深度）。
  2. **最大坡度 $s$**：$\max(|h_{0,0}-h_{1,0}|, |h_{0,0}-h_{0,1}|, |h_{1,0}-h_{1,1}|, |h_{0,1}-h_{1,1}|)$。
  3. **材質類別 $t$**：`boden.txt` 中對應 $4\times 4$ cell 的材質名稱（全圖庫共 2,961 種材質標籤）。

## 五、代表性官方地圖分析

深入檢視各類代表地圖的具體數據，可揭示原版設計的真實結構：

### 1. 無盡模式代表：`ENDL_000`（草原河流）
- 阻擋網格數：9,738 / 65,536（14.86%）
- 水面下判定 ($d > 0$)：Precision = **0.1883**，Recall = **0.1567**（TP: 1,526, FP: 6,580, FN: 8,212）
- 聯合模型：Precision = 0.9495，Recall = 0.8762
- **關鍵現象**：大量的淺水區在視覺上處於水面下，但在 `collision.bmp` 中為 0（允許部隊涉水渡河）；同時，河岸兩側平坦地面卻被大量手工塗黑（阻擋），用於引導部隊進入特定淺灘與隘口。

### 2. 戰役無水陸戰圖：`KAMP_002`（山地要塞）
- 水位高度：`Waterlevel = 0`，全圖無水。
- 阻擋網格數：6,972 / 65,536
- 坡度門檻判定 ($s > 12$)：Precision = **0.0412**，Recall = **0.0029**
- **關鍵現象**：阻擋幾乎全為戰術關卡、山谷邊界與不可通行的人造障礙，其高程坡度極其平緩，坡度法則完全失效。

### 3. 海島／水網戰役圖：`KAMP_002_i`（深水防禦）
- 阻擋網格數：27,950 / 65,536（42.65%）
- 水面下判定 ($d > 0$)：Precision = **0.9268**，Recall = **0.9979**
- 最佳水深門檻 ($d > 112$)：Precision = **0.9931**，Recall = **0.9895**
- **關鍵現象**：本圖為少數達標地圖（5/73 之一），因為該地圖為標準深水孤島，島外皆為深海，無複雜涉水淺灘；然而一旦同一套門檻套用至 `ENDL_001` 或 `KAMP_024`，Recall 立即暴跌至 0.04 以下。

### 4. 教學地圖：`TUTOR_01`（192×192 小型圖）
- 阻擋網格數：7,224 / 36,864（19.60%）
- 水面下判定 ($d > 0$)：Precision = **0.2890**，Recall = **0.2331**
- 坡度判定 ($s > 12$)：Precision = **0.4698**，Recall = **0.6856**
- **關鍵現象**：地圖邊界與教學走道完全由關卡企劃人工塗製，非單純由地形高度自動生成。

## 六、材質（Texture）關聯性檢驗

分析 `raw-textures.csv`（共 2,961 個材質記錄），檢驗材質是否能對應通行屬性：
1. **矛盾材質範例**：
   - `4B5___50`（岩石／懸崖材質）：可通行 4,109 格、阻擋 37,763 格（阻擋率 90.2%）。同一材質在多張地圖中既作為可行走步道，又作為不可通行山壁。
   - `4B2___50`（草地／泥土材質）：可通行 2,234 格、阻擋 10,550 格（阻擋率 82.5%）。
   - `3UGH__03`：可通行 48 格、阻擋 48 格（阻擋率恰好 **50.0%**）。
   - `4B6___50`：可通行 1,856 格、阻擋 2,384 格（阻擋率 **56.2%**）。
2. **Bayes 誤差（Exact Feature Minority）**：
   在許多地圖中，具有完全相同（材質標籤, 水深數值, 坡度數值）的網格，同時存在通行與阻擋兩種標註。全圖庫累計的貝氏不可分網格數達數萬格，證實輸入特徵不足以單值映射至輸出。

## 七、結論與架構決策

依據使用者要求與統計證據：
1. **否定全域自動通行判定**：
   官方地圖的 `collision.bmp` 屬於**關卡設計者手動繪製的導航網格（Level Designer Authored Navigation Mesh）**，並非由高度、坡度或材質經由單純演算法渲染產生。手動繪製包含了涉水淺灘（Ford）、視野隔斷、邊界防禦與 AI 行軍路徑等遊戲性意圖。
2. **符合終止條件**：
   使用者明確規範：「*If a rule is reliable (e.g. >0.95 precision and recall on most maps), implement an opt-in "自動更新通行層"... If not reliable, document and stop without code.*」
   因所有規則皆未達標，**恪守指示終止程式碼變更，不實作猜測性自動更新**。
3. **保留既有局部水域筆刷**：
   維持現有 `TerrainHeightEditSession.PaintWater` 機制：設計者明確選取水域筆刷下挖時，僅在筆刷區域內將原為 0 的通行處標為 255，且絕不主動清除未知來源之阻擋（保有手動畫記 Provenance）。
4. **驗證與建置結果**：
   - `dotnet build AgainstRomeModifier.slnx -c Release --nologo`：**0 個錯誤、0 個警告**。
   - `dotnet test AgainstRomeMapEditor.Modules.Tests`（地形核心測試）：**24 通過、0 失敗**。
   - `dotnet test AgainstRomeModifier.Tests`（地形整合測試）：**21 通過、0 失敗**。
   - 合計 **45 通過、0 失敗、0 略過**。
