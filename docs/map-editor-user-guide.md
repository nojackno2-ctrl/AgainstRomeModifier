# 羅馬帝國地圖編輯器使用者指南 (Map Editor User Guide)

本文件說明 Against Rome 地圖編輯器的完整功能與操作流程，涵蓋地形起伏、通行性、地表材質、自然景觀、物件與部隊放置、配置與基地生成、事件觸發器系統、AI 戰役波次企劃，以及多 AI 協同製圖工作流程。

---

## 1. 系統環境與執行前置需求

1. **執行環境**：
   - 從原始碼執行需 **.NET 8 Desktop Runtime**；自包含發行版已包含執行環境。
2. **遊戲目錄與存取權限**：
   - 編輯器需要讀取遊戲安裝目錄（預設為 `C:\Program Files (x86)\Against Rome`）以載入官方物件範本、字體與部族定義。
   - 若遊戲安裝在受系統保護的目錄，編輯器在儲存自製地圖（如 `ENDL_005`）時需要具備相應的寫入權限，否則可能發生檔案存取被拒。
   - 自製地圖名稱與文字需符合 **CP1251** 編碼字元集。輸入中文或 emoji 時，欄位會顯示提示；拒絕儲存會保留編輯內容，修正後可重試。
   - 標題與隊伍名稱可使用引號、反斜線與 tab，不能含換行或 NUL；跳脫後的單一文字常數上限為 **100 位元組**（例如反斜線會佔兩個位元組）。多行簡報會自動拆成符合限制的常數，避免溢位。
3. **本機 AI 前置需求（選用）**：
   - 若使用多 AI 製圖功能，需於本機啟動 **Ollama** 服務（預設埠 `11434`），並預先下載 `laguna-xs-2.1:latest`。三個角色依序執行，一次只發送一個推論請求。

---

## 2. 核心編輯工具

### 地圖檢查

右側「地圖檢查」分頁按「立即檢查」，會列出放置物件座標／身份、事件設定／目標、起始部隊阻擋、建築工地回退、錨點重疊、NavMesh 道路缺口與通行區連通問題。選取問題可閱讀完整說明；雙擊或按「定位」跳到對應物件或事件，具座標的問題同時置中畫面。編輯後結果標為可能過時，須重新檢查後定位。

儲存前會自動檢查。錯誤會取消寫入、保留編輯內容並切到檢查分頁；警告仍可儲存。連通性以 `collision.bmp` 與高度／水位的四方向區域估計，未模擬遊戲碰撞體積、部隊散開、建築占地或動態尋路；腳本生成的起始單位也可能不在放置清單。因此阻擋、連通與錨點重疊僅作提醒，仍需實機驗證。

修改器的「全部還原」會先顯示選項，**預設保留自製地圖**。取消勾選「保留自製地圖」才會刪除已登記且帶標記的自製圖；原廠圖與外來圖不在刪除範圍。還原與刪除在同一交易中，失敗會嘗試恢復地圖及登記資料。未登記的標記圖或既有刪除暫存目錄會使刪除流程中止，需先檢查其狀態。

### 2.0 3D 場景（原遊戲畫面）

- 3D 場景直接使用遊戲安裝目錄中的原始素材（`alr.dat`、`apt.dat`、`objdef.dau`、`SYSTEM/cl_alr.ini`、`SYSTEM/cl_apt.ini`）唯讀顯示建築、單位、樹木、岩石、柵欄等物件；缺少這些檔案時退回彩色標記點。
- 視角與遊戲相同：正交等角投影（俯角 30°），畫面比例可切成與遊戲 1:1。
- 地表套用地圖 `vertex.bmp` 的烘焙光照。
- 地圖 DATA 中的所有物件（樹木、岩石、原版建築等）都會顯示；遊戲中看不見的腳本標記以青色小點提示。
- 建築顯示完工外觀；樹木由樹幹與樹冠兩層合成；單位以隊伍顏色顯示，預設朝向與遊戲中角度 0 相同。
- 操作：滑鼠滾輪或 PageUp/PageDown 縮放；方向鍵依畫面方向捲動；Home 回到遊戲 1:1 比例；中鍵拖曳平移；右鍵拖曳旋轉（旋轉後預先繪製的物件不會跟著轉）。
- 「移動選取物件」模式：直接點選畫面上看得到的物件即可選取（單擊只選取不移動），拖曳超過 4 像素才移動，移動時保持抓取位置並對齊格子中心；3D 檢視取得焦點時按 Delete 可切換刪除（儲存前可再按一次還原）。點到樹木、岩石等自然物件時按 Delete 會移除該物件（此模式下「復原／重做」先作用於這類移除）；放置物件與地圖固定物件（原版建築、柵欄等）會提示改用對應工具。
- 「放置物件」模式：游標所在格子會顯示所選物件的半透明預覽，跟隨物件類型與隊伍設定。
- 2D 俯視圖也以原始素材縮圖顯示場景物件。
- 物件依遊戲的陰影素材（`shad.dat`）在地面畫出陰影，位置與大小同遊戲。
- 單位播放待機動畫，主屋火把、煙霧等建築動畫同步播放；樹木等地景維持靜態。
- 放置的部隊依遊戲隊形（`formdef.dau` 第 0 號）顯示全部士兵與旗幟；點選任一士兵即選取該部隊（隊形為近似，遊戲中會再依碰撞散開）。
- 勾選「遊戲光照」可預覽指定時刻的環境色與火盆、火把等局部光源光暈（預設關閉，編輯時維持中性顯示）。
- 右下角小地圖可點擊或拖曳跳轉視野，並以黃色標記目前位置（2D 時為可見範圍）。
- 放置／自然物件清單顯示每種物件的原始素材縮圖；單位會依放置角度顯示朝向。

#### 目前限制

- 光照預覽未含雲影、地形陰影時段與光源閃爍，建築以地面錨點單點取樣（遊戲為逐區塊）；225° 以上與騎兵的朝向換算未在遊戲內實測；地形不會遮擋其後方的物件；草地等多重散佈類物件只顯示單一圖像。

### 2.1 地形與通行編輯 (Terrain & Passability)

- **高度工具 (Height)**：
  - 支援六種操作：**升高 (Raise)**、**降低 (Lower)**、**平滑 (Smooth)**、**整平 (Flatten)**、**粗糙 (Roughen)** 與 **水面（下挖）**。
  - 提供三種強度：**輕 (Gentle)**、**中 (Medium)**、**強 (Strong)**。
  - **整平模式**：滑鼠點擊起點的頂點高度會自動鎖定為目標高度基準，拖曳時將範圍內地形平滑過渡至該高度。
  - **筆刷內插**：支援 Bresenham 軌跡補點，快速拖曳筆刷時不會產生間隙斷點。
- **通行區域 (Passability)**：
  - 直接編輯 `collision.bmp`。
  - 支援 **阻擋 (Block)**（紅色覆蓋層，單位無法通行）與 **可通行 (Passable)**（清除阻擋）。
- **通行區域顯示**：在通行編輯模式，2D 與 3D 都以紅色覆蓋阻擋區域；繪製、復原／重做、儲存與重開會同步更新。切換其他工具後隱藏覆蓋。
- **顯示恢復**：缺少高度圖或素材庫、OpenGL 初始化失敗時會退回 2D 並提供診斷。補回資源後按「重試顯示」，重新載入顯示素材並嘗試重建失敗的 OpenGL context，保留未儲存文字、地形修改與復原／重做歷史。素材損壞時保留原素材庫與編輯；3D 仍不可用時可繼續使用 2D。
- **3D 原遊戲畫面**：見 2.0 節。
- **地表材質與混合 (Texture & Blend)**：
  - 支援圓形筆刷繪製地表材質；編輯器會根據原版材質轉移規則進行混合。若材質組合超出原版過渡圖層支援範圍，系統會自動略過並給出提示。
  - **土路 (Dirt Path)**：調色盤「道路」分類的土路使用原版 `PFAD` 圖塊（原版地圖最常用的道路），用一般筆刷拖曳即可，邊緣與轉角由編輯器自動選用原版邊界片。原版邊界只為 L2 草地／土地繪製；其他顏色相近的地表也可使用（自動挑選草地或土地邊界組），交界處可能有輕微色差。兩條路斜向只碰到一個角時沒有原版片，會被略過並提示，請改用 3×3 以上筆刷。
- **圖塊印章 (Tile stamp)**：
  - 勾選「圖塊印章（原版道路、河流、岩壁…）」可直接選取原版圖塊印章，拖曳會補齊游標回報之間的格子。一次拖曳提交為一次單步 Undo 交易；切換筆刷會開始新筆畫。
  - **地區圖塊篩選 (`_stampOtherRegions`)**：勾選「圖塊印章」後會顯示「顯示其他地區圖塊」核取方塊。系統預設會檢查地圖貼圖目前使用的 L 系列圖塊；若貼圖不含 L 圖塊，則檢查地圖上的地景物件地區（日耳曼 GER=L2、匈人 HUN=L3、不列顛 BRI=L4/04、義大利/羅馬 ITA/ROM=L5/05/06、喀爾巴阡 KAR=L13/15）。在未勾選且無搜尋關鍵字時，清單僅顯示符合地圖地區的 L 圖塊，防止誤用不相容氣候的圖塊；若輸入搜尋文字或勾選「顯示其他地區圖塊」，則顯示素材庫中的所有地區圖塊。
  - **自動選路 (`_autoRoad`)**：勾選「圖塊印章」後會顯示「自動選路（拖曳自動轉向與路口）」核取方塊。啟用後可在 2D 畫布與 3D 視圖中進行連續筆畫拖曳，系統會記錄拖曳軌跡（`_roadStrokePath`），並依據目前選取的印章偏好圖塊（如 `PFAD` 或道路圖塊），由 `RoadTileCatalog` 與 `TerrainBlendEditSession.PaintRoadPath` 自動匹配原版直路、轉向彎角、T 字路口、十字路口與端點片。若拓撲連接缺少對應方向的原版圖塊，狀態列會提示無法連接；放開滑鼠一次提交整條路徑，按 Escape 或取消會復原回繪製前的原始地表圖塊。
- **區域工具與懸崖工具 (Region Tools & Cliff Tool)**：
  - 工具列「區域工具…」（或在 3D/2D 檢視中按住滑鼠拖曳「框選」矩形後自動代入對角圖格座標）提供多種大面積批次運算：
    - **矩形懸崖岩壁 (Cliff Face)**：由 `CliffEdgeDetector` 讀取 257×257 頂點高程場 (`_terrainLayers.Heights`)，依高度落差與地圖步長偵測矩形範圍內的陡坡格與坡向。圖塊目錄（`CliffTileCatalog.BuildRealNames`）嚴格僅使用經原版圖塊像素分析驗證之真實岩壁圖塊（北坡 `Fels_AA_008`、東坡 `Fels_AA_004`、南坡 `Fels_AA_002`、西坡 `Fels_AA_006`），嚴格要求精確朝向，禁止猜測名稱或轉角回退（避免遊戲內出現「Error: File not found」錯誤圖塊）。目前 16 個轉角朝向會安全略過並在狀態列提示略過數量。套用時在 4×4 碰撞網格寫入阻擋像素（每格 16 阻擋像素，防止單位翻越懸崖），並自動嘗試銜接坡腳碎石過渡（碎石邊界缺失時發出警告但不阻擋懸崖套用）。支援紋理與碰撞雙層 session 單步原子 Undo/Redo。
    - **矩形水系河流 (River Flow)**：自動規劃水系流向，下挖河床至水面以下並保持 3 頂點平滑岸坡過渡。
    - **矩形生態植被散播 (Flora Scatter)**：依地形高程與生態圈規則自動散播適應當前氣候的植物。
    - **矩形水力與熱力侵蝕 (Erosion)**：模擬水力沖刷與熱風化侵蝕地形高程。
    - **城牆／柵欄折線 (Wall / Palisade)**：依據航點沿線以 64 世界單位間距排列真實城牆物件（Pal00/Pal01/Pal02 等）。
- **重設平坦地形 (Reset Flat Terrain)**：
  - 把地形整平到水位換算後的高度樣本 + 20，清除碰撞阻擋與可移除地景、重設基礎材質；聚落、腳本與連結物件保留。
  - 地圖選單的「平坦範本地圖」會完整複製無盡範本，再將這些地形變更放入待儲存狀態。它是保留範本內容的整平流程。
  - 「空白場景（實驗）」是獨立流程：清除來源物件、聚落物件定義與編輯器事件，以新的等待腳本取代原開局生成，清除13份執行期資料池，並在建立槽位前寫好平坦材質／高度／通行層。複製空白圖會保留獨立腳本模式，原無盡 AI 修補不套用到此模式。不會自動提供起始部隊、聚落、資源或敵方 AI；需要自行放置物件與事件。派系／人口、環境及其他 DATA 池仍沿用範本，**遊戲開局尚未驗證**，見 [空白場景契約](map-editor-blank-map-contract.md)。

### 2.2 自然物件編輯 (Nature Objects)

- **底層架構**：直接讀寫地圖 `DATA/objects.dat`、`objdata.dat` 與 `position.dat` 中的靜態景觀資料槽位。
- **操作模式**：
  - **種植 (Plant)**：依照選取類別，沿拖曳路徑經過的格子放置景觀物件。每次放置均帶有隨機微調之旋轉角度。
  - **移除 (Remove)**：清除筆刷覆蓋範圍內的樹木、草叢、灌木或岩石。
- **物件類別**：
  - 樹木 (Trees)、草叢與花 (Grass & flowers)、灌木 (Bushes)、蘆葦與水生植物 (Reeds & water plants)、岩石 (Rocks)、其他地景 (Other)。
- **安全邊界**：
  - 嚴格排除地圖中的腳本標記 (Skriptmark) 與關聯物件，避免破壞遊戲原本的邏輯點位。
  - 地圖世界物件數量嚴格限制於上限 **14,000 個**，超過時會拒絕新增以防存檔損毀。

### 2.3 放置物件：建築與部隊 (Placed Objects)

- **完工建築 (Prebuilt Buildings)**：
  - 支援隊伍 0 至 8（隊伍 0 為玩家，隊伍 8 為中立）。
  - **完工範本機制**：儲存時會沿用既有建築自身的安全 DATA 範本，或比對官方地圖同類型的完工建築範本 (`Bau*`)，直接將完工建築寫入 `DATA/objects.dat`。既有範本只在持久 ID、alias、runtime UID 仍匹配且物件未連結時沿用，避免官方素材副本不完整時，修改部隊連帶將完工建築改為工地。
  - 若建築沒有可沿用的 DATA 範本，也缺乏官方完工範本，系統會自動退回透過腳本生成（進入遊戲時為 0% 工地狀態）。儲存成功訊息與放置分頁會列出已儲存為腳本工地的建築類型；重新開圖仍會顯示。範本恢復後編輯並儲存，可改回 DATA 完工建築。
- **人物與部隊 (Characters & Units)**：
  - 透過在 `SCRIPT/ak_level.bci` 主程式開頭注入腳本 shim 來建立。
  - **隊伍 0** 為玩家控制單位。
  - 人數支援 1–20；單兵也走部隊容器生成流程，保持事件目標的身份語意一致。
- **編輯、複製與刪除**：
  - 選取一個放置物件可編輯隊伍、座標、角度與人數，保留原持久 ID。
  - 多選後按「隊伍／方向…」，勾選要修改的設定並套用；整批保留位置、人數與事件目標身份，一次復原可還原整批。混選部隊時隊伍限0–7；只選其他物件時隊伍範圍沿用原放置規則。取消不修改內容。
  - 多選複製／刪除會整批執行，在「放置物件」模式下只需一次撤銷即可還原整批。
  - 複製產生新 ID，X/Z 各偏移 256；若任何複本超出 X/Z 0–16383，整批拒絕且保留原物件與撤銷歷史。
  - 儲存失敗會保留待存變更與歷史；修正錯誤後可重試。成功儲存才更新基準、清除待存新增與放置／自然物件的歷史。
- **持久目標標識 (Persistent Target ID)**：
  - 每個放置物件均獲配一個唯一的持久 `Guid Id`。在存檔重建 DATA 槽位或位元碼時，皆以該 ID 作為關聯基準。
- **擺放安全距離限制**：
  - **重要提醒**：編輯器會檢查建築附近的自然物件並提示保留空間；此提示不保證遊戲內生成成功，確切碰撞條件仍需實機驗證。

### 2.4 配置與基地生成 (Layouts & Settlement Generator)

編輯器主視窗選單列設有「配置」(Layout) 選單，提供聚落配置、對戰基地一鍵生成以及自訂配置範本的匯入與匯出：

- **一鍵生成對戰基地… (`SettlementGeneratorDialog`)**：
  - 支援 **2 至 8 位玩家** 的對戰基地自動規劃（2 位玩家採用中心對稱 `CentralSymmetry`，3–8 位玩家採用旋轉對稱 `RotationalSymmetry`）。
  - 支援四大部族切換：**日耳曼 (Germanic)**、**羅馬 (Roman)**、**塞爾特 (Celtic)**、**匈人 (Hun)**。
  - 支援 **0 至 999999** 的隨機種子碼（提供「隨機種子」按鈕快速抽換）。
  - 提供核取方塊「生成周邊森林與採石場（自然地景物件）」(`IncludeNature`)。
  - 核心由 `SettlementSiteEvaluator` 評估地勢平坦度、避開水面與碰撞阻擋網格；`ResourceClusterPlanner` 在主屋周邊生成對應的木材林區與採石場；`MultiplayerFairnessBalancer` 保障各家基地至資源點的公平對稱距離。
  - 物件使用經過實機別名比對之真實識別碼（日耳曼主屋 `BauGerHau00_Haupthaus`，匈人以 `SCHLA` 屠宰場代替農場等；周邊野生動物使用 `FigTieEbe00` 野豬且隊伍設為中立 -1 以單一物件生成，避免部隊生成限制報錯）。
  - 同時套用至 `PlacementEditSession` 與 `NatureEditSession`，主表單提供跨層單步原子 Undo/Redo 連動。
- **保存與載入配置**：
  - 「保存選取的聚落／物件…」：將目前選取的放置物件儲存為 `.arm-layout.json` 範本。
  - 「保存森林區域…」：以矩形區域保存地景森林配置。
  - 「載入並套用配置…」：將已儲存的配置範本套用至當前地圖。

## 3. 事件與觸發器系統 (Scenario Events & Triggers)

編輯器提供類似《世紀帝國 2》的觸發器機制，將自訂邏輯注入地圖腳本主迴圈。

### 3.1 規格限制
- **事件上限**：全圖最多 **256 個** 事件。
- **動作上限**：每個事件支援 **1–32 個** 動作。
- **條件上限**：每個事件支援 **0–32 個** 條件（全部條件成立才觸發，AND 邏輯）。若無條件則純粹依照計時觸發。
- **計時設定**：延遲時間為 0–86,400 秒。若勾選「重複執行 (Repeat)」，間隔至少需為 1 秒。

### 3.2 條件類型 (Conditions)
所有條件均需綁定已放置的目標物件（透過持久 ID 關聯）：
1. **物件存在 (`ObjectExists`)**：
   - 檢測目標物件是否存活或實體仍存在於場景中（包含尚未消失的部隊或建築殘骸）。
2. **物件死亡或移除 (`ObjectDeadOrRemoved`)**：
   - 目標必須**曾被腳本輪詢確認存在**，之後死亡或被清除時才會成立。若開局建立失敗則不視為死亡。
   - 即使計時尚未到期，系統在背景也會持續追蹤目標狀態。
3. **物件位於矩形區域 (`ObjectInArea`)**：
   - 檢測目標物件的世界座標是否進入 `[MinX, MinZ]` 至 `[MaxX, MaxZ]` 的閉區間內（邊界值包含端點）。
   - 部隊單位以整隊容器的中心座標進行判定。

### 3.3 動作類型 (Actions)
動作依清單順序由上而下執行：
1. **顯示訊息 (`Message`)**：
   - 呼叫 `s_showTextBox` 彈出對話框。文字長度上限 1,000 位元組，需為 CP1251 字元。
2. **改變外交 (`Diplomacy`)**：
   - 呼叫 `s_setTeamHostile` 設定指定兩支隊伍（0–7）之間為敵對或和平。
3. **生成部隊 (`SpawnUnit`)**：
   - 於指定世界座標動態生成指定隊伍（0–7）與人數（1–20）的部隊。
4. **勝利 (`Victory`) / 失敗 (`Defeat`)**：
   - 設定腳本全域變數 `GLOBAL_MISSION_RESULT` 並呼叫 `s_quitGame` 結束任務。
   - **規則限制**：勝敗動作必須是**單次事件（非重複）的最後一個動作**。

### 3.4 視覺化事件節點圖 (Visual Event Graph)

在右側「事件」分頁中，可切換「清單檢視」與「節點圖」檢視：
- 節點圖以雙緩衝畫布呈現事件流向，支援拖曳節點、新增/刪除連接線。
- 編輯節點圖時會標記為草稿狀態；點擊「套用節點圖」前會執行完整語法與流控驗證，拒絕孤立或不可編譯的無效結構。
- 套用時透過 `ScenarioEventSession` 原子替換事件集合，支援單步 Undo/Redo。

### 3.5 AI 戰役波次企劃… (`CampaignWaveDialog`)

位於「配置」(Layout) 選單中的「AI 戰役波次企劃…」（位於「一鍵生成對戰基地…」下方）：
- **啟用條件**：地圖必須為自製地圖 (`IsCustom == true`)、事件圖無未套用草稿 (`!_eventGraphDirty`)，且目前事件總數未滿 256 個上限。
- **企劃參數設定**：
  - **原型 (`Archetype`)**：從四大戰略原型（日耳曼戰團、羅馬防線、匈人騎兵、塞爾特突襲）中選擇。**重要合約**：原型僅用於提供兵種偏好別名（如 `GER_INF01`、`ROM_INF00` 等真實遊戲別名）；不傳遞勢力 AI、戰術、擴張或經濟設定。
  - **波次數 (`Waves`)**：1 至 256 波（預設 3 波）。
  - **首波時間（秒）(`First wave`)**：開局後多少秒產生第一波（0–86,400 秒，預設 60 秒）。
  - **波次間隔（秒）(`Interval`)**：後續各波次之間隔秒數（1–86,400 秒，預設 60 秒）。
  - **每兵種人數 (`Count per unit type`)**：每種兵種每波生成的士兵人數（1–20 人，預設 10 人）。
  - **隊伍 (`Team`)**：進攻波次的隊伍歸屬（0–7，預設 1）。
  - **生成點世界座標 (`Spawn X`, `Spawn Z`)**：部隊生成的世界座標（0–16,383，預設 8000, 8000）。
- **即時預覽與驗證**：
  - 對話框即時呼叫 `CampaignMissionCompiler.Compile` 與 `ScenarioEventValidator`。
  - 若合併後的總事件數超過 256 個上限或包含無效條件，預覽文字方塊會顯示 `[Error]` 診斷並停用「合併事件」按鈕。
  - 驗證成功時顯示每波生成的延遲時間與部隊內容，並啟用「合併事件」按鈕。
- **支援與限制說明**：
  - **目前僅支援定時部隊生成**。
  - 移動/巡邏路徑 (`AssignedPathId`)、指定攻擊目標物件 (`TargetObjectId`)、部隊相對延遲 (`RelativeDelaySeconds`) 以及勢力 AI 戰術姿態等設定，尚未由底層 ScenarioEvent ABI 支援；編譯器會**明確報錯拒絕而非靜默忽略**。
  - 點擊「合併事件」後，波次事件會透過 `ScenarioEventSession.AddRange` 原子加入事件清單，可單步 Undo/Redo；儲存地圖時才寫入檔案。

## 4. 多 AI 共同製圖流程 (Multi-AI Map Planning)

編輯器支援透過本機 Ollama 讓多個 AI 角色分工協同生成地圖。

### 4.1 三大設計角色與職責劃分
1. **地形角色 (Terrain Specialist)**：
   - 負責規劃山丘 (hill)、山脈 (mountain)、山谷 (valley)、高原 (plateau)、山脊 (ridge)、通行阻擋 (blocked) 與通行路徑 (passable)。
   - 擁有設定全圖基礎高度 (`baseHeight`) 的權限。
   - 特徵配額：最多 8 個特徵。
2. **水系角色 (Water Specialist)**：
   - 負責規劃湖泊 (lake) 與河流 (river)。
   - 特徵配額：最多 8 個特徵。
3. **材質角色 (Materials Specialist)**：
   - 負責規劃地表材質覆蓋區域 (material)。
   - 擁有設定全圖基礎材質 (`baseMaterial`) 的權限。
   - 特徵配額：最多 8 個特徵。
- **整體配額**：三個角色合計最多 24 個特徵，各角色職責獨立，防止彼此擠佔配額。

### 4.2 模型選擇建議 (Role Model Choice)
三個角色預設均使用 `laguna-xs-2.1:latest`，依地形、水系、材質順序執行。可手動指定模型；同一編輯器程序內的規劃器共用單一推論鎖，以降低本機資源需求。

### 4.3 規劃生命週期：檢視 → 套用 → 儲存
1. **生成 (Generate)**：輸入地圖描述後點擊「生成／重試」。系統會依固定角色順序向 Ollama 發送請求，一次執行一個。
2. **方案檢視 (Plan Review)**：
   - AI 生成後的方案**不會直接套用地圖**。
   - 使用者可在「方案檢視」視窗中檢視各角色的成功狀態、警告訊息（如無效特徵過濾、重複去除、配額截斷）以及詳細的規劃摘要與特徵座標清單。
3. **套用方案 (Apply Plan)**：
   - 「地圖預覽」分頁以目前編輯狀態的獨立快照顯示方案：藍色為水域、紅色為阻擋，橙點為材質變更、紫點為材質拒絕區域。這是示意圖，並非遊戲渲染；預覽不改地圖、撤銷歷史或檔案。
   - 「方案與診斷」列出預計變更量及材質接受／拒絕數。生成中顯示目前角色、模型及完成角色數（0–3），不預估模型推論時間。
   - 確認方案合理後，點擊「套用方案」。
   - 系統會依序轉換高度點、材質區域與通行像素，並即時更新 2D 畫布與 3D 視圖。
4. **地圖儲存 (Save)**：
   - 套用僅更新記憶體中的編輯工作區，**尚未寫入磁碟**。
   - 關閉對話框並檢視主地圖後，按下主畫面的「儲存地圖」(Ctrl+S) 才會透過單一復原交易安全寫入檔案。

### 4.4 取消與部分失敗處理 (Cancellation & Partial Failure)
- **取消生成**：在生成過程中可隨時點擊「取消生成」，背景請求會安全中斷，不會殘留半成品至地圖。
- **部分失敗 (Partial Failure)**：若其中一個角色失敗（例如模型回應超時、JSON 語法錯誤或無有效特徵），協調器會整合其餘成功角色的特徵產生「部分方案 (Partial Plan)」。
  - 對話框會明確提示「部分角色失敗：這是未完整的方案」，並在檢視區列出失敗角色的錯誤訊息。
  - 使用者可選擇套用這份部分方案，或修改描述後重新生成。

### 4.5 撤銷與復原行為 (Undo Mode Behavior)
- AI 方案的高度與通行編輯合併為同一筆歷史；在「高度」或「通行」模式按 **Ctrl+Z**，會一起撤銷這兩類變更。
- 材質使用獨立歷史。在「材質」模式按 **Ctrl+Z**，可一次撤銷這份方案中已接受的材質區域；若要還原整份方案，還需切換至「高度」或「通行」模式撤銷。
- 原版材質不支援的區域會被拒絕，先前已接受的區域仍保留。套用結果會顯示拒絕數量，請檢視地圖後再儲存。
- 亦可點擊「還原地表」還原至最近成功儲存的地形基準；尚未儲存時則還原至開圖狀態。

## 5. 驗證現況與界限說明 (Verification Limits)

為維持開發透明度，各模組功能的驗證層級說明如下：

| 功能項目 | 本輪程式碼與測試驗證 | 遊戲內實機狀態 |
| :--- | :--- | :--- |
| 高度、通行、基礎材質、自然物件、放置 | Session 交易、撤銷重做與合成地圖測試通過 | 基礎地貌與單位已於歷史實測中驗證 |
| 圖塊印章（地區篩選、自動選路） | `RoadTileCatalog` 拓撲匹配與連續筆畫撤銷測試通過 | 遊戲內路面顯示未驗證 |
| 區域工具（懸崖岩壁、河流、侵蝕、城牆） | 頂點偵測、真實圖塊解碼、碰撞阻擋與雙層 Undo 測試通過 | 懸崖岩石貼圖已確認顯示，碎石過渡與侵蝕未確認 |
| 一鍵生成對戰基地 (`SettlementGenerator`) | 4 族真實別名、2–8 人平衡分布、雙層 Undo 測試通過 | 建築茅草屋與雞舍已確認出現，人口與平衡未確認 |
| 視覺化事件節點圖 (`EventGraph`) | 畫布繪製、圖結構驗證與原子替換測試通過 | 節點圖操作之事件在遊戲內結算未確認 |
| AI 戰役波次企劃 (`CampaignWaveDialog`) | 編譯器、原型真實別名、驗證預覽與 256 筆上限測試通過 | **未在遊戲內驗證**（僅定時生成部隊可編譯） |
| 天候與大氣 (`BodenIniSerializer`) | 33 鍵真實 INI 校準、預設選單與存檔交易測試通過 | 暴風雨粒子與夜晚光照已在歷史實測中可見 |
| NavMesh 診斷與道路修復 | 64 網格紋理換算、4x4 碰撞像素清除與撤銷測試通過 | 尋路改善未在遊戲內驗證 |
| 模組打包與安裝 (`ModBundleExporter`) | Manifest 1.1、ZIP 打包校驗與連續槽位安裝測試通過 | 模組包安裝後之遊戲清單顯示未驗證 |

### 實驗性或未接入模組說明 (Experimental & Unwired Modules)

以下模組目前僅存在於 `src.MapEditor.Modules` 架構或具備原型測試，**尚未接入編輯器 WinForms UI 或地圖存檔流程**，或因缺乏原版引擎契約而保持停用：

1. **環境音效 (Soundscape / Sound Zones - `src.MapEditor.Modules/Soundscape`)**：
   - **現狀**：**未接入 UI，原生匯出已停用 (Unwired / Experimental)**。
   - **逆向證據**：經對照原版遊戲地圖檔案，發現原生地圖 DATA 目錄下根本沒有 `sound.dat`；遊戲原生聲音來自 `sfxenv/sfxobj/sfxexp.dau` 與物件 action 觸發。因缺乏原版環境音效表與空間音效播放合約，`SoundscapeBinaryStorage` 已全面阻擋虛構的 `sound.dat` 匯出與腳本注入（呼叫即拋出 `NotSupportedException`）。僅保留編輯器內部的 SNDZ 草稿格式與記憶體預覽。
2. **運鏡導演 (Cinematics / Camera Director - `src.MapEditor.Modules/Cinematics`)**：
   - **現狀**：**未接入 UI 與關卡腳本 (Unwired / Experimental)**。
   - **逆向證據**：已於 EXE 中確認底層原生原語 `s_lgcSetEnginePos v(ddd)` 與 `s_lgcSetEngineZoom v(d)`（原生縮放夾限 0..9），且 `CinematicBciCompiler` 已實作底層 bytecode 呼叫片段編碼。但航點預覽距離換算、Pitch/Yaw 原生參數對應、相機控制權接管/釋放、黑邊效果及腳本時間軸排程仍無原生證據。模組宣告為 `IsExperimental = true; IsWiredToLevelScript = false;`，未接入主程式 UI。
3. **戰役任務目標 (Objectives / Mission Goals - `src.MapEditor.Modules/Objectives`)**：
   - **現狀**：已接入編輯器 WinForms UI（配置選單「任務目標設計…」）與事件存檔流程；遊戲內行為尚未驗證。
   - **逆向證據**：`BciObjectiveCompiler` 嚴格保守降階至既有的 `ScenarioEvent`（僅支援單一主要目標、目標物件死亡/移除 `ObjectDeadOrRemoved`、開局生存倒數、護送至矩形區域、保護物件失敗等）。沙盒 `ObjectiveSandboxSession` 支援的依賴圖 (Prerequisites)、多主線目標、隊伍全殲、持續佔領 (King of the Hill)、擊殺/資源計數在編譯匯出時均會被嚴格阻擋。
4. **野外巢穴與生物 (Wild Lairs & Wildlife - `src.MapEditor.Modules/WildLair`)**：
   - **現狀**：已接入編輯器 WinForms UI（配置選單「野外巢穴守衛波次…」）與事件存檔流程；遊戲內行為尚未驗證。
   - **逆向證據**：逆向分析確認原版引擎無野外巢穴 (den) 或定期再生 (spawn trigger) 機制；野生動物在 DATA 中為中立（隊伍 8）單一物件（`FigTie` 類別，如 `ALL_WOL00`, `ALL_BAE00`, `ALL_EBE00`, `ALL_RAU00`）。`WildLairScenarioEventBinder` 僅能將特定步兵的定時波次降階至 `ScenarioEvent`；動物單兵生成（`SpawnUnit` 不支援隊伍 8）、動態守衛、死亡重生、資源/榮譽獎勵等原生無支援而直接拋出例外。

> [!NOTE]
> 本輪未存取遊戲安裝目錄，亦未啟動遊戲執行。所有新功能與修正均以原始碼分析、單元測試（Modules Tests）與宿主 STA 測試（Modifier.Tests）為準，切勿宣稱本輪版本已完成遊戲內驗收。
