# Against Rome 地圖檔案格式技術文件

本文件記錄《Against Rome》（決戰羅馬/蠻族入侵）地圖目錄下的檔案格式分析結果，為開發獨立地圖編輯器提供數據結構基礎。

## 1. 地圖目錄結構
每個地圖檔案夾（如 `MAPS/TUTOR_00/`）主要由以下部分組成：
*   **根目錄 BMP 檔案**：定義地形、高度與碰撞阻擋。
*   **DATA/ 目錄**：二進位資料檔（皆使用 `PFIL@` 壓縮封裝），定義物件、座標、路徑與營地資訊。
*   **SCRIPT/ 目錄**：關卡腳本（如 `ak_level.bci`）。
*   **TEXT/、TEXTUREN/**：語言與材質相關配置。

---

## 2. 地形與高度（BMP 圖像）
地圖的幾何與表面材質直接由標準 24bpp BMP 格式影像定義，尺寸通常為 192x192 或 193x193（含頂點偏移）：
*   **`vertex.bmp` (193x193)**：頂點高度圖。亮度值（或 RGB）決定地形起伏高度。
*   **`boden.bmp` (193x193)**：地表材質分配圖（定義草地、沙地、岩石等紋理索引）。
*   **`collision.bmp` (192x192)**：碰撞阻擋圖。定義地圖上的可通行區與不可通行區（如懸崖、深水）。
*   **`smooth.bmp` (193x193)**：材質過渡平滑參數。
*   **`emboss.bmp` (193x193)**：地形浮雕/法線陰影效果。
*   **`minimap.bmp` (192x192)**：遊戲內 UI 顯示的小地圖縮圖。

## 3. DATA/ 二進位資料格式
DATA 目錄下所有以 `.dat` 結尾的檔案均經過 `PFIL@` (LZSS) 壓縮。

### 3.1 壓縮封裝（PFIL@ 格式）
*   **標頭 (Header)**：前 64 位元組。其中第 16-19 位元組（Little-Endian Int32）儲存**解壓縮後的真實大小**。
*   **演算法**：使用特化的 LZSS 演算法，環狀視窗大小為 4096 位元組（初始化前 4078 位元組為 `0x20` 空格，後 18 位元組為 `0x00`）。專案中已於 `src/Core/GameLZSS.cs` 完整實作編解碼器。

### 3.2 關鍵檔案結構分析
所有地圖的 `.dat` 檔案在解壓後皆為**固定大小**，因為遊戲引擎採用了預分配固定槽（Fixed slots）設計。

#### A. `objects.dat` (解壓後大小：1,694,016 位元組)
*   **檔案標頭**：前 16 位元組 `(v1, v2, v3, v4)`，其中 `v2 = 14000` 表示最大物件容納量。
*   **雙陣列結構**：
    *   **陣列 1 (物件定義與名稱)**：`14000` 個元素，每個元素 **79 位元組**（總計 1,106,000 位元組，緊接在 16 位元組標頭後）。
        *   `0x00 - 0x01` (2 bytes)：類別/子類別識別碼（如 `01 08`）。
        *   `0x02 - 0x03` (2 bytes)：物件索引 (ID)。
        *   `0x04 - 0x05` (2 bytes)：X / Y 網格粗略座標。
        *   `0x06 - 0x07` (2 bytes)：常數/狀態旗標（如 `33 00`）。
        *   `0x08 - 0x25` (30 bytes)：物件類型名稱字串（Null-Terminated ASCII，如 `"Testobject"`）。
        *   `0x26 - 0x43` (30 bytes)：物件 ID 字串（Null-Terminated ASCII，如 `"id_Testobject"`）。
        *   `0x44 - 0x4E` (11 bytes)：額外屬性與狀態位元組。
    *   **陣列 2 (物件運行時狀態/陰影等資料)**：`14000` 個元素，每個元素 **42 位元組**（總計 588,000 位元組）。

#### B. `position.dat` (解壓後大小：561,008 位元組)
*   **檔案標頭**：前 8 位元組（包含元素數量 `33000`）。
*   **資料陣列**：`33000` 個元素，每個元素 **17 位元組**（總計 561,000 位元組）。
    *   `0x00 - 0x0B` (12 bytes)：三維浮點數座標 `(Float X, Float Y, Float Z)`，決定物件在地圖上的精確 3D 位置。
    *   `0x0C - 0x0F` (4 bytes)：浮點數旋轉角度（Rotation）。
    *   `0x10` (1 byte)：狀態或旗標位元組。

#### C. 其他相關檔案
*   **`objdata.dat` (解壓後 1,722,008 位元組)**：物件的細部屬性與開局狀態。
*   **`lager.dat` (解壓後 144,016 位元組)**：地圖聚落/營地（Siedlung）的定義與配置。
*   **`way.dat` (解壓後 791,052 位元組)**：路徑與 AI 尋路網格點。
