# Application table generation

`tools/app_tables.json` is the canonical, editable application string data.
It was seeded from the frozen managed-table snapshot. The independent
`tests/fixtures/app_tables_expected.json` remains an unchanged historical oracle;
never regenerate that fixture as part of table generation.

The JSON object requires exactly `ZH`, `EN`, `EN_UNIT_NAMES`, and
`ZH_UNIT_NAMES`. Each value is an array of two-string arrays (key, value).
Array order and duplicate keys are preserved. Object member order does not
affect output: tables always appear in the order listed above.

From the repository root:

```text
cargo run -p against-rome-ambience --example generate-app-tables --locked --offline --target-dir native/against-rome-ambience/target --
cargo run -p against-rome-ambience --example generate-app-tables --locked --offline --target-dir native/against-rome-ambience/target -- --check
cargo test -p against-rome-ambience --all-targets --locked --offline --target-dir native/against-rome-ambience/target
```

Generation uses only Rust and existing crate dependencies; no C# sources,
PowerShell script, new dependency, or runtime API change is required.
Input and default output paths are resolved from `CARGO_MANIFEST_DIR`, so the
example also works from other working directories. `--output PATH` overrides
the output (relative paths use the current working directory).

Output is UTF-8 without BOM, with LF newlines and a final newline. The original
table bytes are preserved except for the generator header. Rust quotes,
backslashes, NUL, CR, LF, and tabs use explicit escapes; other control characters
use Rust Unicode escapes. Readable Unicode and format placeholders stay intact.

`--check` compares exact bytes, returns failure for stale or missing output, and
never writes or creates that output. The tests compare generated bytes with the
checked-in file, canonical data with every frozen entry in order, and the public
tables with the same oracle. They also cover escaping, strict schema parsing,
idempotence, and no-write checks against fresh, stale, and missing files.

Intentional future text changes will require an explicit decision about the
historical parity tests; the generator itself must never update the oracle.
